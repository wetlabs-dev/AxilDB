# Care Cadence Research

Care research generates persistent proposals. It never activates a schedule or changes specimen overrides, disabled activities, care events or initial due dates. Approval writes the same definition cadence used by manual configuration and dynamic inheritance.

## Research and review

Server administrators with verified two-factor authentication can open **Server Management → Care Cadence Research**. Research shows actual missing-activity counts, dependency blocks, previous applicability decisions and persistent job progress. Review groups proposals by definition or shows a compact table, with definition/activity/confidence/status/source filters and name/activity/date/confidence sorting. History retains decisions and original recommendations.

**Research Missing Cadences** queues one priority job per eligible definition in active collections with AI features and AI Curator enabled. Existing active work is retained. Enable AI Curator and run the existing `ai-curator` Docker worker; the browser can close. Priority 1000 puts cadence jobs ahead of ordinary queued research, without interrupting an in-progress call. Existing model, credentials, token settings, budgets, usage tracking and retry settings apply. Worker wakes serialize across processes. Provider requests time out after two minutes; interrupted cadence leases recover after ten minutes with bounded attempts and backoff. Exhausted jobs require a deliberate Retry. Cancel prevents an in-flight response from publishing proposals; provider costs already incurred remain recorded.

Magic Fill husbandry includes the same structured recommendation instructions and validation in its existing request. On saved definitions it persists missing recommendations separately and previews them. Server administrators can select and approve specific recommendations. Saving husbandry alone does not approve cadences. Unsaved definitions need to be saved first. Existing **Research now** also queues missing cadence research through AI Curator. Fertilizer recipe assignment and descriptive husbandry research retain their responsibilities; they no longer write AI-generated numeric fertilizer cadence fields as a side effect.

Research uses botanical identity/taxonomy, description, structured husbandry and the assigned recipe, excluding specimen/acquisition/user details. Recommendations include confidence, rationale, references and applicability. Fixed watering intervals are cautious starting points: inspect moisture and account for substrate, light, pot, temperature, humidity and season. A condition-based activity may be not applicable or have insufficient information. References are model-supplied, not independently verified; prompts prohibit invented citations. No live AI call is necessary for installation.

**Approve** allows editing the approved interval and unit while retaining the original recommendation. **Reject** preserves the result without scheduling it. **Approve All Eligible** first fetches the current eligible set and shows its actual proposal and distinct-definition counts in a cancellable confirmation. It applies only that confirmed set, rechecking each record transactionally; results distinguish approvals and skip reasons. A recipe removed after preview causes a skip. Manual cadence configuration supersedes conflicting pending proposals. Database locks, unique constraints and missing-only inserts protect against simultaneous manual changes and approvals. Bulk operations can partially succeed and can safely be retried.

An active same-collection fertilizer recipe must already be assigned directly to the definition for fertilizing research/approval. Available collection recipes and a proposed draft assignment do not qualify. Blocked fertilizing is excluded from work and approval. Previous rejections, not-applicable and insufficient results suppress routine spending. Use explicit **Re-research** for a selected definition to revisit those decisions; first review any pending actionable proposals. Insufficient or not-applicable recommendations may be rejected to record a review; they never activate zero-day intervals.

## Legacy investigation and recovery

Repository history before `e2d898d` calculated watering from broad text categories (3/5/7/10/18 days, default 7), pest inspections from susceptibility/pest names (14/21/default 30 days), and repotting from prose with approximate day conversions. Those watering/pest guesses were computed at queue-read time, not stored as definition cadence records. Fertilizing used numeric guide/recipe fields or parsed frequency text. The inherited cadence migration retained the husbandry fields, migrated explicit numeric settings, and stopped the implicit guesses.

The existing local `backups/axildb.dump` was inspected read-only with a compatible PostgreSQL client. Its archive dates to August 24, 2026 and contains 23 husbandry guides, including explicit watering, repotting and fertilizer frequency text. It predates AI Curator tables. No production database was inspected or modified and the archive was not restored into any application database. Existing AI Curator stores suggested JSON and Magic Fill stores approved husbandry text; older raw Magic Fill responses were not archived by the endpoint. Backup manifests and migration artifacts contain no separate schedule store.

**Recover previous cadence data** scans retained definition husbandry fields. It extracts unambiguous positive integer day/week/month/year intervals from `wateringCadence`, `repottingInterval`, `fertilizationFrequency`, or numeric `fertilizationCadenceDays`. Ambiguous ranges, descriptive categories and invalid values are skipped. Fertilizing additionally requires the assigned active recipe and an unpaused legacy guide. Existing configured cadences and pending proposals are preserved. Repeated recovery uses a stable original-value fingerprint to avoid duplicates, even after rejection. Results are labeled **Recovered from previous cadence data**, with the original field/text in the rationale; review is mandatory. No new model-generated value is described as recovered.

Recovery also inspects retained AI Curator husbandry/fertilizer suggestion JSON for explicit intervals, retaining the original suggestion ID in its rationale. It never treats an unapplied draft as an approved cadence.

Recovery does not import an archive or restore missing definitions. If current source fields have been cleared, restore a backup into a separate, access-controlled database, inspect only the relevant original definition/guide records, and prepare a separately reviewed import mapping original definition IDs before using recovery. Do not restore a backup over production to recover care text. The archive may contain older values and sensitive unrelated information. Non-numeric prose and runtime guesses cannot be faithfully recovered as stored intervals.

## Deployment and verification

Deploy migration `20261018190000_care_cadence_research`, regenerate Prisma and redeploy app and existing worker together. No automatic recovery, AI calls or approvals run during migration. The migration adds proposal constraints, one pending proposal per activity, one active cadence job per definition, a manual-configuration supersession trigger, and changes the older Curator scope index to cover active jobs only so explicit re-research can retain terminal history.

`npm run check:cadence-research` uses a disposable migrated database to exercise the real services with a deterministic provider stub, including restart recovery, budgeted worker integration, usage tracking, concurrent/edited approvals, partial batches, recovery and inheritance. `npm run check:cadence-research:ui` exercises administrator review and permissions against the local test app. Real provider response quality requires review with your configured model; automated tests do not spend tokens or validate external botanical sources.
